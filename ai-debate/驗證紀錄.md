## ❌ 仍未驗證

- **`codex exec` 沒有成功取得過回覆**：測試容器的網路出口擋掉了 `api.openai.com`，
  也沒有 ChatGPT 登入。參數正確、程式有跑起來，但「codex 回一段話、主持台讀回來」這條路
  還是只在紙上。請在 Ula 的電腦上用 `python debate.py --check` 補這一步。
- **Windows 實機**：`shell=True` 呼叫 npm 裝的 `claude.cmd` / `codex.cmd`、`.bat` 拖放、
  右鍵選單（`install_context_menu.py` 需要 `winreg`，只能在 Windows 跑）都還沒在 Windows 上試過。
- **長篇討論的額度消耗**：沒有量過一場完整討論實際花多少。

## 這次順手修掉的問題

1. **錯誤訊息被雜訊蓋掉**：codex 連不上時會把同一行重連錯誤刷幾十次，舊寫法只截最後 1500 字，
   結果看到的全是 `Reconnecting...`，真正的原因被推出畫面。現在會去掉時間戳與重試計數後去重，
   只留最後幾行不同的內容（實測 31 行雜訊收斂成 4 行有效訊息）。
2. **逾時看不出原因**：`subprocess.TimeoutExpired` 其實帶著子行程逾時前寫到 stderr 的內容
   （POSIX 上是 bytes、Windows 上是 str），舊寫法丟掉了。現在一併印出來，
   所以「超過 N 秒沒有回應」後面會直接跟著 CLI 自己說的原因。
3. **空白回覆被當成成功**：codex 的正式回覆只在 `--output-last-message` 指定的檔案裡
   （橫幅和進度都走 stderr）。舊寫法在結束碼為 0 但檔案空白時會回傳空字串，
   讓一則空白發言進入紀錄。現在空白一律視為失敗並報錯。
4. **失敗了還繼續燒額度**：舊寫法某一步兩邊都失敗時，只記錄錯誤就繼續跑下一步。
   以 3 輪討論為例，等於在明知會失敗的情況下再跑十幾個步驟、每步最多等 900 秒。
   現在一步之內沒有任何一方成功發言就停下整個排程並清空佇列。
5. **存檔可能壞掉**：`state.json` 是直接覆寫的，存檔中途按 Ctrl+C 會留下壞掉的 JSON，
   那一場就讀不回來了。改成先寫 `.tmp` 再 `os.replace` 置換。
6. **找不到指令的錯誤訊息**：改成先用 `shutil.which()` 解析再執行，
   `DEBATE_CLAUDE_CMD` / `DEBATE_CODEX_CMD` 寫成完整路徑（含引號）也能正確解析。
7. **新增 `--check`**：各問一句極短的話確認兩個 CLI 會回話。第一次使用先跑這個，
   不用開一整場討論才發現沒登入。
