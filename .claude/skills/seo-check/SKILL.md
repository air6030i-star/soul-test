# seo-check｜網站健檢

## 執行

```bash
bash lifeos/scripts/health-check.sh
```

腳本會檢查五項，逐項回報通過或問題清單。

## 五項檢查

### 1. Meta 覆蓋

每個頁面都該有 `<title>`、`meta description`、`og:` 系列、`canonical`。
**目前基準（2026-09-30）**：只有 `index.html` 有完整 og，`canonical` 全站都沒有。
→ 這是已知缺口，回報時標成「既有問題」，不要當成新發現。

### 2. 定價一致性（最容易出事的一項）

歷史上出過多次定價不同步事故。腳本會列出全站所有 `NT$` / `US$` 出現位置。

判讀：
- 同一個產品在不同頁面出現**不同金額** → 錯誤，要修
- 出現已下架的舊價 → 錯誤，要修
- NT$ 與 US$ 並存是正常的（雙幣別），但兩者的**換算比例**要一致

**改價一律先 `grep` 全站，一次改完，不要只改一頁。**

### 3. 內部連結

抓出所有 `href="..."` 指向本站檔案的連結，檢查檔案是否存在。
歷史事故：親子交付頁 Pro 直鏈打錯字（`export` 寫成 `download`）。

### 4. 中文編碼

歷史事故：**雙重 UTF-8 亂碼**。腳本會找出典型亂碼字串（`ä¸`、`æ`、`ç`、`ï¼`）。
有命中就是編碼壞了，不是內容問題。

### 5. 頁數與方案描述

`grep` 頁數描述（`10 頁`、`19 頁` 等），確認各頁說法一致。

## 輸出

```
網站健檢 <YYYY-MM-DD>

[通過] <項目>
[問題] <項目>：<檔案:行號> <說明>

建議修的順序：
1. <最高優先，說明為什麼>
```

## 紅線

- **只回報，不自動修。** 修正要走 `03_草案協定.md` 出草案。
- 不要為了讓檢查通過就改動已上線頁面的文案語意。
