# task-intake｜一件事進來

## 步驟

1. 讀 `lifeos/000_Agent/01_分流判斷.md`，照判斷表由上往下比對，得出 A–F。
2. 判斷不了 → 寫進 `lifeos/100_Todo/inbox/`，標 `#待分流`，**停在這裡**，不要開始做。
3. 讀對應的 `lifeos/000_Agent/routes/<路線>.md`。
4. 在 `lifeos/100_Todo/projects/` 開檔案，檔名 `YYYY-MM-DD-<對象或主題>.md`，frontmatter：

```markdown
---
路線: <A-F>
狀態: 待開始
對象: <沒有就寫 待補>
截止: <沒有就寫 待補>
預估工時: <分鐘，估不出來寫 待補 並說明>
實際工時: 待補
---
```

5. 照 `lifeos/000_Agent/03_草案協定.md` 產出草案，**一次只給一份**。
6. 停下來等「確認 / 修改 / 取消」。

## 輸出格式

```
分流：<路線字母>・<路線名>
理由：<命中判斷表第幾條>
檔案：lifeos/100_Todo/projects/<檔名>
待補欄位：<列出來，沒有就寫「無」>

草案編號：draft-YYYYMMDD-<路線><序>
草案版本：v1
預估工時：<分鐘>
有效期限：24 小時

--- 內容 ---
<草案本體>
---

請回覆：確認 / 修改 / 取消
```

## 不要做

- 不要在分流不明時硬選一條
- 不要自行填補「待補」欄位
- 不要在使用者確認前執行草案內容
