# client-proposal｜接案與報價

走 `lifeos/000_Agent/routes/D_接案與內訓.md`。

## 步驟 1：需求清單（缺的一律寫「待補」，不要用常識補）

| 項目 | 內容 |
|---|---|
| 日期／時間／時長 | |
| 地點 / 線上平台 | |
| 對象、人數、程度 | |
| 主辦希望聽眾帶走什麼 | |
| 預算範圍 | |
| 講義／錄影／後續 Q&A | |
| 決策者、答覆期限 | |

**「待補」≥ 3 項 → 不要報價。** 改成產出一則可直接傳給對方的提問訊息草案，問清楚再回來。

## 步驟 2：工時

```
準備（含客製）＋ 交通 ＋ 台上 ＋ 事後（講義修訂／Q&A／請款） = 總工時
```

參考 `lifeos/200_Reference/private/報價歷史.md`。**沒有歷史資料就寫「待補」，不要憑空給金額。**

## 步驟 3：報價草案

走 `03_草案協定.md`，路線 `D`，並掛一個 `E・財務管理` 子任務（請款、應收）。

## 紅線

- **Agent 不寄信、不回訊息。** 只產出可複製的版本。
- 不可以替使用者答應日期、價格、範圍。
- 客戶名稱、金額、聯絡方式只寫進 `lifeos/200_Reference/private/`，**不進 git**。
