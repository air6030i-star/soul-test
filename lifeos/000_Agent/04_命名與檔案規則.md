# 04｜命名與檔案規則

> 目的只有一個：**不要每次都重新想東西該放哪。**

## 資料夾結構

```
lifeos/
├── 000_Agent/          規則層。agent 的大腦，進 git，可公開
│   └── routes/         A–F 六條路線的 SOP
├── 100_Todo/           ⛔ 不進 git
│   ├── inbox/          剛進來、還沒分流
│   ├── projects/       進行中的案子，一案一檔
│   └── archive/        （保留，實際封存走 900_Archive）
├── 200_Reference/      參考資料
│   ├── （根層）        可公開的：產品原則、範本、規格
│   └── private/        ⛔ 不進 git：客戶偏好、報價歷史、合約
├── 300_Journal/        ⛔ 不進 git。YYYY-MM/YYYY-MM-DD.md
├── 900_Archive/        已封存，YYYY/ 分年
└── scripts/            工具腳本
```

編號留空是故意的（000/100/200/300/900），中間要插新分類時不用重排。

## 檔名規則

| 類型 | 格式 | 範例 |
|---|---|---|
| 案子 | `YYYY-MM-DD-<對象或主題>.md` | `2026-10-15-某某企業內訓.md` |
| 日誌 | `YYYY-MM-DD.md` | `2026-09-30.md` |
| 參考資料 | `<主題>.md`，用詞不用日期 | `報價話術.md` |
| 草案暫存 | `draft-YYYYMMDD-<路線><序>.md` | `draft-20260930-D1.md` |

規則：

- **日期一律 `YYYY-MM-DD`**，不要用 `10/15`、`1015`、`115`
- 檔名不要有空白，用 `-`
- 中文檔名可以，但不要混雜全形標點（`：？！（）`）
- 不要在檔名寫狀態（`最新`、`final`、`v3-真的最後`）——狀態寫在檔案內的 frontmatter

## 案子檔案的 frontmatter

```markdown
---
路線: D
狀態: 進行中        # 待開始 / 進行中 / 等對方 / 完成 / 取消
對象: 待補
截止: 2026-10-15
預估工時: 120
實際工時: 待補
---
```

`狀態` 只能用上面那五個值，不要自創。

## 新增檔案的預設位置

不確定放哪 → `100_Todo/inbox/`，標 `#待分流`。
**不要為了放這一個檔案就新開一個資料夾。**
同一類東西累積到 **5 個以上**，才考慮開子資料夾。
