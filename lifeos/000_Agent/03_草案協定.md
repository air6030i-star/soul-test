# 03｜草案協定

> **Agent 產出的一切都先是草案。** 沒有我明確說「確認」，不得對外送出、不得寫進正式檔案、不得排進行事曆。

## 草案格式

每一份草案都要有完整標頭：

```
草案編號：draft-20260930-A1
草案版本：v1
路線：D・接案與內訓
標題：10/15 企業內訓報價
預估工時：120 分鐘
有效期限：24 小時（至 2026-10-01 20:59）

--- 內容 ---
（草案本體）
---

請回覆：確認 / 修改 / 取消
```

### 欄位規則

| 欄位 | 規則 |
|---|---|
| 草案編號 | `draft-YYYYMMDD-<路線字母><流水號>`，例：`draft-20260930-C2` |
| 草案版本 | 從 v1 開始。我要求修改後 +1，內容重做也不重新編號 |
| 路線 | A–F，要跟分流結果一致 |
| 預估工時 | **一定要給**，用分鐘。不會估就寫「待補」並說明為什麼 |
| 有效期限 | 預設 24 小時。超過期限我沒回覆 → 草案作廢，要重新產 |

## 我的回覆只有三種

| 回覆 | Agent 動作 |
|---|---|
| **確認** | 執行草案內容；正式檔案落地；回寫記憶 |
| **修改** + 說明 | 版本 +1，重出草案，**不要直接執行** |
| **取消** | 標記作廢，回寫「取消原因」，不追問 |

我如果回了別的（例如只講一句感想），**當成「修改」處理，不要當成確認。**

## 一次只給一份

- 同一件事一次只產一份草案，不要同時丟三個版本讓我挑
- 真的需要選項時，在同一份草案裡列 **2–3 個方向**，並標出你建議哪個、為什麼

## 草案失效的情況

- 超過有效期限
- 我針對同一件事給了新資訊
- 依據的前提改變（對方改期、預算變動、規格變更）

失效後**不要沿用舊草案內容直接執行**，重新產一份。
