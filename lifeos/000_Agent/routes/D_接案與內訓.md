# D・接案與內訓

**進入條件**：這件事的客戶是別人——接案、主持、企業內訓、合作邀約、講座。

> 這是一人公司最貴的一條路線：它同時消耗時間、精神跟品牌。
> **所以每一步都要留下記錄，不是為了流程，是為了下次報價不要再靠感覺。**

## 步驟

### 1. 建案子檔案

在 `100_Todo/projects/` 開 `YYYY-MM-DD-<對象>.md`，frontmatter 見 `04_命名與檔案規則.md`，`路線: D`。

### 2. 把需求問清楚

以下沒問到的一律寫「待補」，**不要用常識填**：

- 日期、時間、時長
- 地點 / 線上平台
- 對象是誰、幾個人、他們的程度
- 主辦希望結束後聽眾帶走什麼
- 預算範圍
- 需不需要講義／錄影／後續 Q&A
- 決策者是誰、什麼時候要答覆

**「待補」超過 3 項就不要進入報價**，先把問題整理成一則可直接傳給對方的訊息草案。

### 3. 算真實工時

報價要算的不只是台上時間：

```
準備（含客製）＋ 交通 ＋ 台上 ＋ 事後（講義修訂／Q&A／請款）
```

歷史資料在 `200_Reference/private/報價歷史.md`（不進 git）。
沒有歷史資料 → 預估寫「待補」並說明缺什麼，不要憑空給數字。

### 4. 報價草案

路線標 `D`，走 `03_草案協定.md`。
金額相關的部分同時掛一個 **E・財務管理** 子任務。

### 5. 我確認後才對外

**Agent 不寄信、不回訊息。** 產出可直接複製的版本。

### 6. 交付前檢查

- [ ] 講義／簡報最終版已存進案子資料夾
- [ ] 時間、地點、聯絡人再確認一次
- [ ] 器材、網路、備援方案
- [ ] 請款資料（抬頭、統編、匯款）已備妥

### 7. 結案回寫（這一步不可以省）

```markdown
> 結案：YYYY-MM-DD｜結果：完成
> 預估 ⟨X⟩ 分 / 實際 ⟨Y⟩ 分
> 報價 ⟨金額⟩｜時薪換算 ⟨金額/(Y/60)⟩
> 下次注意：⟨一句話⟩
```

把時薪換算寫進 `200_Reference/private/報價歷史.md`。
**連續三次實際工時超過預估 30%，就要主動提出來——那是報價模型該調整了。**
