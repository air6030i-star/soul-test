# A・每週例行

**進入條件**：這件事每週／每月固定會再發生一次，且沒有外部急迫期限。

**典型內容**：週計畫、週回顧、趨勢整理、網站健檢、對帳前的資料整理、社群固定發文排程。

## 步驟

1. **確認這是例行還是偽例行**
   如果它只發生過一次、你「覺得」以後會固定做——那不是例行，走 F。
   例行的定義：**已經連續發生過 3 次以上，或我明確說它是固定的。**

2. **對照例行清單**
   讀 `lifeos/200_Reference/例行任務清單.md`。
   沒在清單上 → 先問我要不要加入，不要自己加。

3. **產出本週草案**
   格式見 `03_草案協定.md`，路線標 `A`。
   內容包含：這次要做的項目、預估工時、跟上週的差異。

4. **等我確認**

5. **執行**
   例行任務的重點是**一致性**，不要每次都換格式。
   跟上次的產出比對，格式不同就是錯了。

6. **回寫**
   寫進 `300_Journal/`，並更新 `200_Reference/例行任務清單.md` 的「上次執行」。

## 這條路線的常見錯誤

- 把臨時的事包裝成例行，塞進週計畫裡拖延 → 有期限的走 B
- 每週重新設計格式 → 例行的價值在於不用重想
- 清單越加越長，最後沒人做 → **一項例行任務連續兩週沒做，就提出來問要不要砍掉**
