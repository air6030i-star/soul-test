# E・財務管理

**進入條件**：這件事會產生收入或動用金錢——報價、請款、對帳、支出、訂閱、稅務。

> **所有金額、帳號、發票資料都在 `200_Reference/private/`，永遠不進 git。**

## 步驟

### 1. 分類

| 類型 | 動作 |
|---|---|
| 收入（待請款） | 記進應收清單，設追款提醒 |
| 收入（已入帳） | 對帳、核銷應收 |
| 支出（一次性） | 記帳，判斷是否可列成本 |
| 支出（訂閱制） | 記帳 + 記下次扣款日 **+ 標註是否還在用** |
| 稅務 | 只整理資料，**不做稅務判斷**（見下方紅線） |

### 2. 記錄

寫進 `200_Reference/private/帳務/YYYY-MM.md`：

```markdown
| 日期 | 類型 | 項目 | 金額 | 對象 | 狀態 |
|---|---|---|---|---|---|
| 2026-09-30 | 收入 | 待補 | 待補 | 待補 | 待請款 |
```

**缺哪一欄就寫「待補」，不要推算。**

### 3. 月結（每月最後一個工作日，由 A・每週例行 觸發）

產出月結草案：

- 本月收入 / 支出 / 淨額
- 應收未收清單（含逾期天數）
- 訂閱支出總額 + **本月沒用到的訂閱**
- 跟上月的差異，只講變化超過 20% 的項目

### 4. 訂閱體檢（每季）

一人公司最容易漏的錢在這裡。逐項問：

- 這個月用過嗎？
- 有沒有功能重疊的另一個？
- 降級會少掉什麼？

產出「建議取消 / 建議降級 / 保留」三欄，**不要自己去取消任何服務**。

## 紅線

- **不做稅務、法律判斷**。只整理資料，結論交給會計師。
- 不可以自動執行任何付款、取消、轉帳
- 金額只寫有憑據的，一塊錢都不要估
- 客戶名稱、帳號、統編不進 git
