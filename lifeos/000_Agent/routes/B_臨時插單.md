# B・臨時插單

**進入條件**：有明確外部期限，且期限在 72 小時內。

**典型內容**：臨時主持邀約、客戶急件、平台審核要補件、活動前一天改流程。

> 這條路線的目的不是「趕快做完」，是**保護其他已排定的事不被打亂**。

## 步驟

1. **先算真實成本，再答應**
   產出一份「插單影響評估」，三件事講清楚：
   - 這件事要多久（分鐘）
   - 它會擠掉哪些已排定的事
   - 擠掉的那些事新的時間是什麼

   **在我看到這三點之前，不要幫我答應任何事。**

2. **給我三個選項**
   - 接，並把 ⟨某某⟩ 往後延
   - 接，但縮小範圍（明確寫出砍掉什麼）
   - 不接，附一段可以直接用的婉拒草稿

   標出你建議哪個，說明理由。

3. **我確認後才動手**

4. **執行時只做最小範圍**
   插單不是重做的時機。能用既有範本就用，不要順手優化。

5. **回寫（這條特別重要）**
   記錄：誰插的單、什麼理由、花了多久、擠掉了什麼。
   **累積 5 筆以上就主動提出來給我看**——同一個來源反覆插單，是要處理的結構問題，不是每次都咬牙撐過去。

## 紅線

- 不可以替我答應時間、價格、範圍
- 不可以因為「很急」就跳過草案確認
- 超過 72 小時期限的，不是 B，回去重新分流
