# 02｜記憶回寫與封存

> 原則：**隨生隨寫，不等結束。** 一件事在進行中就開始回寫，不要等到全部做完才補記錄——那時候細節已經掉了。

## 什麼時候回寫

| 時機 | 寫什麼 |
|---|---|
| 草案被我確認的當下 | 確認了什麼版本、我改了哪裡 |
| 事情有實質進展時 | 進展 + 卡點 |
| 事情結束 | 結果、實際工時 vs 預估、下次要改什麼 |
| 事情被取消 | 取消原因（這個最容易忘，但最有用） |

## 回寫到哪裡

| 內容性質 | 位置 |
|---|---|
| 這個案子的進度 | 該案子在 `100_Todo/projects/` 的檔案內 |
| 今天發生什麼 | `300_Journal/YYYY-MM/YYYY-MM-DD.md` |
| 之後還會用到的知識、範本、對方偏好 | `200_Reference/` |
| 只跟這一次有關、之後用不到 | 不用另外寫，留在案子檔案裡就好 |

**判斷標準：三個月後的我還會需要這句話嗎？** 會 → `200_Reference/`。不會 → 留在原地。

## 回寫格式

在案子檔案底部累加，最新的在最上面：

```markdown
## 記錄

### 2026-09-30
- 狀態：進行中 → 等對方回覆
- 做了：寄出報價草案 v2（調整工時 120 → 90 分鐘）
- 卡點：對方還沒給場地資訊，影響器材清單
- 下一步：10/02 前沒回覆就主動追
```

## 封存

### 觸發條件

- 案子狀態變成 `完成` 或 `取消`
- **且** 記錄已經寫完最後一筆

### 封存動作

1. 把 `100_Todo/projects/<案子>.md` 移到 `900_Archive/YYYY/`
2. 在檔案最上方補一行結案摘要：

```markdown
> 結案：2026-09-30｜結果：完成｜預估 120 分 / 實際 165 分｜下次注意：場地資訊要在報價前就問
```

3. 如果過程中產出了可重複使用的東西（範本、話術、清單），**先抽出來放進 `200_Reference/`**，再封存

### 不要做的事

- 不要刪除，只移動
- 不要為了「看起來乾淨」提早封存還在跑的事
- 封存後不要再改內容，要補充就開新檔案並連過去
