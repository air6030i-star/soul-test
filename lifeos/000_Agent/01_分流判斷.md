# 01｜分流判斷

> **收到任何一件事，先走這份。** 分流後只會進 A–F 其中一條，不會同時走兩條。
> 不管走哪條，最後都匯回 `02_記憶回寫.md` 與封存，不會留在半路。

## 全程地圖

```
起點（訊息／想法／排程時間點）
        │
        ▼
   分流判斷 ── 誰來？內容？對應哪個 Skill？
        │
  ┌─────┼─────┬─────┬─────┬─────┐
  ▼     ▼     ▼     ▼     ▼     ▼
  A     B     C     D     E     F
每週  臨時  內容  接案  財務  自有
例行  插單  創作  與內訓 管理  產品
  └─────┴─────┴──┬──┴─────┴─────┘
                 ▼
            記憶回寫（隨生隨寫，不等結束）
                 ▼
               封存
```

## 分流判斷表

**由上往下比對，第一個命中的就是答案。**

| # | 判斷條件 | 路線 |
|---|---|---|
| 1 | 這件事**有明確外部期限**（客戶／主辦／平台給的），且期限在 72 小時內 | **B・臨時插單** |
| 2 | 這件事會**產生收入或動用金錢**（報價、請款、對帳、支出、稅） | **E・財務管理** |
| 3 | 這件事的客戶是**別人**（接案、主持、企業內訓、合作邀約） | **D・接案與內訓** |
| 4 | 產出是**要對外發佈的內容**（貼文、文章、影片、SEO、電子報） | **C・內容創作** |
| 5 | 這件事**每週／每月固定會再發生一次** | **A・每週例行** |
| 6 | 以上皆非，是**我自己的產品或想做的事** | **F・自有產品／自主專案** |

### 判斷不了的時候

不要猜。照這個順序處理：

1. 先看「這件事做完，誰會收到東西？」——外部客戶 → D；一般讀者 → C；只有我自己 → F
2. 還是不確定 → 丟進 `100_Todo/inbox/`，標 `#待分流`，**不要開始做**
3. 下次跟我確認時一起問

### 一件事同時符合多條

**選比較上面的那條**，其他的拆成子任務掛在後面。

範例：「接了一場企業內訓，要先報價，結束後要發一篇心得貼文」
→ 主線走 **D・接案與內訓**
→ 報價拆成 E 的子任務
→ 心得貼文拆成 C 的子任務，掛在 D 的收尾步驟後面

## 分流之後

1. 讀對應的 `routes/<路線>.md`，照那份的步驟走
2. 每條路線都會產出**草案**，格式見 `03_草案協定.md`
3. 我確認後才執行
4. 執行完走 `02_記憶回寫.md`
